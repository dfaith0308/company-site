# step4 — siksiki.com 새 관리자로 옮기기

## 왜 만드는가
step1~3은 테스트 주소에서 만든다. 실제 광고를 돌리려면 siksiki.com 자체가 새 관리자로 움직여야 한다.

## 사용자
운영자(대표), 방문자.

## 화면과 흐름
1. 관리자에서 지금 siksiki.com과 똑같은 페이지를 만든다(점검 때 나온 BACKLOG 문제는 이때 같이 고친다: 공유 이미지, 카톡 채널 버튼, 빈 회색 상자, 회사명·연도, 약관 링크 등).
2. 테스트 주소에서 대표가 휴대폰으로 확인.
3. 대표 승인 후 siksiki.com 주소를 새 관리자 쪽으로 연결(배포 — 대표 지시 시에만).
   - 방법: 코드를 복사하지 않는다. Vercel 설정에서 siksiki.com·www.siksiki.com 주소를 company-site 프로젝트에서 빼고 랜딩OS 프로젝트에 붙인다. 랜딩OS는 들어온 주소를 보고 어느 사이트 페이지를 보여줄지 정한다.
   - 도메인 구입처(가비아 등) 설정은 바꿀 필요 없음 — 이미 Vercel을 가리키고 있다(2026-09-28 확인).
   - 되돌리기: 주소를 다시 company-site 프로젝트에 붙이면 된다.
4. 옛 빈 페이지(/os, /ads, /design, /jeongmoo, /shop, /dashboard)는 첫 화면으로 보낸다.
5. 네이버 서치어드바이저 등록, 검색 안내 파일 자동 생성 확인.

## 데이터
- 새로 저장할 것 없음. step1~3의 데이터를 그대로 쓴다.

## 규칙
- 옮기는 동안 siksiki.com이 멈추면 안 된다. 연결을 바꾸는 순간에도 옛 페이지나 새 페이지 중 하나는 보여야 한다.
- 주소는 하나로 통일(www 붙일지 대표 결정, 기본값: www.siksiki.com — 지금 실제 운영 방식).
- 옛 저장소(company-site)는 지우지 않고 보관. 문제 생기면 10분 안에 되돌릴 수 있어야 한다.

## 예외 상황
- 연결 후 새 페이지가 안 열림 → 즉시 옛 저장소로 되돌림.

## 이번에 만들지 않는 것
- 다른 서비스 랜딩 이전 — 식식이로 검증한 뒤 서비스별로 진행.

## 완료 기준
1. siksiki.com에 들어가면 새 관리자에서 게시한 페이지가 보인다.
2. 관리자에서 문구를 바꾸고 게시하면 siksiki.com에 1분 안에 반영된다.
3. 카톡으로 siksiki.com을 보내면 미리보기 사진과 제목이 나온다.
